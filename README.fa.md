# MaGdSubForge

فارسی · [English](README.md)

یک سرویس کوچک Flask که بین پنل **3x-ui** و برنامهٔ VPN کاربران قرار می‌گیرد. ساب JSON پنل را می‌گیرد و **طبق قوانینی که خودتان می‌نویسید** بازنویسی می‌کند: حذف کانفیگ، تغییر ترتیب، ادغام چند کانفیگ در بالانسر (`leastLoad`، `leastPing`، `random` و ...)، عبور دادن outbound خودتان (WARP و ...) از داخل یک کانفیگ خروجی، و تغییر هر بخش دلخواه از JSON.

این پروژه هیچ قرارداد نام‌گذاری و هیچ ارائه‌دهندهٔ خاصی را نمی‌شناسد. شما تعیین می‌کنید هر کانفیگ چیست، چی حذف شود و چی با چی ترکیب شود. بدون قانون، ساب پنل بدون تغییر برمی‌گردد.

> نسخهٔ اولیه (v0.1). تست خودکار دارد ولی هنوز کسی زیاد در محیط واقعی استفاده نکرده. وابسته به 3x-ui نیست.

## نصب روی سرور (یک دستور)

روی یک سرور لینوکسی (Debian/Ubuntu؛ بقیه‌چیز خودکار نصب می‌شود)، با کاربر root:

```bash
curl -fsSL https://raw.githubusercontent.com/mjbe71/MaGdSubForge/main/install.sh | sudo bash
```

نصب‌کننده هر چه لازم دارد می‌پرسد و بقیه را خودش انجام می‌دهد. به ترتیب:

۱. **آدرس پنل.** اگر پنل 3x-ui روی همین سرور باشد، آدرس ساب JSON آن را پیشنهاد می‌دهد.
۲. **HTTPS.** دامنه‌ای که کاربران به آن وصل می‌شوند را بدهید. بعد به این ترتیب: گواهی خودتان اگر مسیرش را بدهید؛ وگرنه گواهی‌ای که از قبل روی سرور هست (مثلاً از 3x-ui)؛ وگرنه یک **گواهی رایگان Let's Encrypt** برای دامنه می‌گیرد (دامنه باید از قبل به همین سرور اشاره کند و پورت ۸۰ برای یک دقیقه آزاد باشد). گواهی‌ها بررسی می‌شوند (معتبر، منقضی‌نشده، کلید مطابق، دامنه پوشش داده‌شده) و تمدیدها خودکار برداشته می‌شوند. اگر در سؤال دامنه Enter بزنید، HTTPS رد می‌شود (فقط HTTP روی localhost).
۳. **پورت** و اینکه **پنل ادمین** (و رمزش) فعال شود یا نه.

بعد سرویسی می‌سازد که با بوت بالا می‌آید و لینک ساب شما را چاپ می‌کند. از آن به بعد:

```bash
sudo magdsubforge help        # وضعیت، لاگ، ری‌استارت، به‌روزرسانی، tls (تغییر HTTPS)، set-admin-password و ...
sudo magdsubforge update      # آخرین نسخه، با حفظ تنظیمات
```

اگر `sudo magdsubforge` را بدون آرگومان اجرا کنید، یک **منوی تعاملی ترمینال** (به انگلیسی) باز می‌شود: وضعیت/لاگ/ری‌استارت سرویس، آدرس پنل، پورت و HTTPS، رمز ادمین، افزودن و ویرایش قوانین/گروه‌ها/زنجیره‌ها/پچ‌ها، پیش‌نمایش و حساب WARP. هر تغییر قبل از ذخیره اعتبارسنجی می‌شود.

همهٔ این‌ها را می‌شود برای نصب بدون سؤال به‌صورت گزینه هم داد (`--panel-url`، `--domain`، `--cert`/`--key`، `--letsencrypt`، `--port`، `--admin`، `--yes` و ...): `install.sh --help`. تنظیمات در `/etc/magdsubforge/config.json` و برنامه در `/opt/magdsubforge` است. حذف: `sudo magdsubforge uninstall`.

> نصب‌کننده با سرورهای شبیه‌سازی‌شده (دیتابیس ساختگی 3x-ui، گواهی آزمایشی و یک جایگزین certbot) تست شده، ولی هنوز روی یک سرور تازهٔ واقعی نه، و مرحلهٔ Let's Encrypt هرگز با سرویس واقعی اجرا نشده. تشخیص 3x-ui اسم تنظیمات را از حافظه می‌خواند؛ اگر چیزی پیدا نکند فقط از شما می‌پرسد. مشکلات را گزارش کنید.

## نصب دستی

پایتون ۳.۹ به بالا (یا Docker) و پنل 3x-ui با **ساب JSON** فعال لازم است.

```bash
git clone https://github.com/mjbe71/MaGdSubForge && cd MaGdSubForge
python3 -m venv venv && . venv/bin/activate
pip install -r requirements.txt
cp config.example.json config.json       # آدرس ساب JSON پنل خودتان را در آن بگذارید
python app.py                            # سرور توسعه
```

آدرس `http://127.0.0.1:8080/sub/<شناسهٔ ساب کاربر>` را باز کنید: ساب پنل را می‌بینید (چون هنوز قانونی ندارید، بدون تغییر).

آدرس ساب JSON را از تنظیمات پنل خودتان پیدا کنید (در 3x-ui معمولاً مسیری مثل `/json/` هست؛ مال خودتان را چک کنید) و در `config.json` به‌عنوان `panel.url` بگذارید؛ شناسهٔ کاربر به انتهایش اضافه می‌شود.

### امتحان قوانین بدون شبکه

```bash
python -m magdsubforge preview examples/sample-panel.json examples/balancers.json
```

نشان می‌دهد هر کانفیگ یک پاسخ ذخیره‌شدهٔ پنل با قوانین `examples/balancers.json` چه می‌شود. با `python -m magdsubforge check config.json` یک فایل را اعتبارسنجی کنید.

### استفادهٔ واقعی

```bash
gunicorn app:app        # آدرس، پورت، worker و HTTPS (server.tls_cert / tls_key) از config.json خوانده می‌شود
```

یا Docker: `mkdir -p data && cp config.json data/ && docker compose up -d --build` (پورت سمت راست در `docker-compose.yml` باید با `server.port` یکی باشد). فایل‌های Docker هنوز توسط نویسنده تست نشده‌اند.

برای HTTPS یا `server.tls_cert` و `server.tls_key` را تنظیم کنید (کاری که نصب‌کننده می‌کند)، یا جلوی سرویس یک reverse proxy با HTTPS بگذارید و **لاگ دسترسی آن را خاموش کنید**، چون آدرس شامل شناسهٔ محرمانهٔ کاربر است (نمونهٔ nginx در README انگلیسی).

## پنل ادمین تحت وب

همهٔ تنظیمات پایین را می‌شود به‌جای ویرایش دستی در مرورگر انجام داد. پنل **به‌طور پیش‌فرض خاموش است**؛ با گذاشتن رمز در `config.json` روشن می‌شود:

```bash
python -m magdsubforge hash-password        # رمز می‌پرسد و یک hash چاپ می‌کند
```

```json
{ "admin": { "password_hash": "<hash را اینجا بچسبانید>" } }
```

بعد `http://127.0.0.1:8080/admin` را باز کنید (مسیر: `admin.path`) و وارد شوید. صفحهٔ **شروع** یک راهنمای مرحله‌به‌مرحله است که همه‌چیز را بررسی می‌کند (دسترسی به پنل، امتحان یک ساب، HTTPS، حساب‌ها، تنظیمات) و تنظیمات رایج را برایتان می‌سازد (پنهان کردن کانفیگ، بالانس، عبور از WARP). تب‌های دیگر فرم‌هایی برای فیلتر، بالانسر، زنجیره، ویرایش پیشرفته و تنظیمات‌اند (به‌علاوهٔ ویرایشگر JSON خام) و یک **پیش‌نمایش زنده** که با جمله می‌گوید هر کانفیگ چه می‌شود. **ذخیره**، `config.json` را می‌نویسد و تغییرات فوراً اعمال می‌شود. فارسی (راست‌به‌چپ) و انگلیسی داخلش هست.

فقط با HTTPS (یا از راه تونل SSH) استفاده کنید، چون رمز در درخواست ورود ارسال می‌شود. تنظیمات ورود (`admin.*`) فقط در `config.json` عوض می‌شوند، نه از داخل پنل.

## تنظیمات

همه‌چیز در `config.json` است و تغییرات بدون ری‌استارت اعمال می‌شود. همهٔ گزینه‌ها در **[docs/config-reference.md](docs/config-reference.md)** (انگلیسی) و نمونه‌ها در `examples/`:

| می‌خواهید | استفاده کنید از |
|---|---|
| حذف یا جابه‌جایی کانفیگ‌ها | `rules` |
| ادغام کانفیگ‌ها در یک بالانسر (به‌ازای هر کشور، پیشوند اسم و ...) | `groups` |
| گذاشتن outbound خودتان (WARP، WireGuard و ...) جلوی یک کانفیگ خروجی | `chains` + `accounts` |
| تغییر هر چیز دیگر (DNS، مسیریابی، mux، fragment و ...) | `patches` |
| تغییر آدرس، پورت، مسیر URL، timeout | `server`، `panel` |

## نکات امنیتی

- شناسهٔ ساب قبل از ارسال به پنل بررسی می‌شود (`server.subid_regex`).
- مسیر عمومی ساب ورود و محدودیت نرخ ندارد (خود شناسهٔ ساب راز است). پورت را محلی نگه دارید و از reverse proxy استفاده کنید. پنل ادمین رمز، کوکی امضاشده، حفاظت CSRF و قفل پس از تلاش‌های ناموفق دارد.
- هرگز `config.json` را commit نکنید (در `.gitignore` هست).
- سرویس هرگز شناسهٔ ساب یا آدرس پنل را لاگ نمی‌کند.

## هنوز نیست

ثبت خودکار حساب WARP برای هر کاربر (`accounts.register`، پیش‌فرض خاموش، با API غیررسمی Cloudflare؛ فقط روی API شبیه‌سازی‌شده تست شده، نه واقعی).
